## 0. Роль и входные данные

Контекст подставляется из канона хранилища: [[Пролог (демо)]], [[01 — Структура прохождения]], [[02 — Механика ХАБа]], [[04 — Модель диалогов и квестов]], [[06 — Квестовый каркас и первая группа NPC]], [[07 — Матрица оператора насосной станции]]–[[11 — Первый диалог с врачом]], [[Стиль диалогов]], [[Принципы повествования]], заметки фракций.

**Жёсткие ограничения канона, которые матрица не должна нарушать:**

- Границы знания игрока (ничего о природе симбиотов, Колонии, роли навигатора).
- Хаб — интерфейс мессенджера ([[02 — Механика ХАБа]]): «прохожих» в демо нет — носители барков это контакты мессенджера + полевой слой у станции.
- Карма меняет тон, а не память; речевой профиль фиксируется до первого эпизода ([[Стиль диалогов]], [[04 — Модель диалогов и квестов]]).

## 1. Теоретическая база: структура и типы диалогов

### 1.1. Структура диалога в проекте ([[04 — Модель диалогов и квестов]])

Иерархия контента:

```text
Контакт NPC
  → независимые эпизоды разговора
    → сообщения (узлы графа)
      → варианты выбора игрока
        → условия, последствия, переходы
```

- **Контакт** — постоянные сведения: идентификатор, имя/аватар, фракция, положение, речевой профиль, отношение по карме (`негатив` / `норма` / `позитив`), список эпизодов.
- **Эпизод** — автономный граф на одно событие или тему: условие запуска, приоритет, признак одноразовый/повторяемый. Единица хранения — один эпизод как отдельный Resource.
- **Сообщение** — узел графа. Типы узлов: текст; запрос; торговля; улучшение у робота; выбор реплики игрока; системное описание результата.
- **Условие** только проверяет состояние (этап квеста, отношения с фракцией, предмет, завершённый эпизод); **последствие** изменяет состояние (квест, отношения, предметы, разблокировка эпизода, фиксация выбора).
- Ветвление — граф со сходящимися узлами; выбор может возвращаться в общий поток (ограничение экспоненциального роста текста).
- Квест отделён от диалога: диалог показывает и меняет состояние квеста, но не хранит его.

Канал доставки ([[02 — Механика ХАБа]]): мессенджер — контакты слева, персональный диалог справа; сообщения могут приходить по инициативе NPC в зависимости от состояния игры; журнал корабля хранит историю.

### 1.2. Принятая типология: роли диалогов в нелинейной игре

**Архитектура — три категории:**

| Категория | Суть | Доступность |
|---|---|---|
| **Сюжетные (гейт-диалоги)** | Происходят только в «точках невозврата», жёстко завязаны на прогресс | По триггеру прогресса |
| **Реактивные (диалоги текущего состояния)** | Персонажи комментируют то, что игрок уже сделал в мире, даже если сюжет не двигается | По флагам мира |
| **Фоновые (дрожжевые диалоги)** | Доступны всегда; углубляют лор и раскрывают характер, пока игрок «гуляет» | Всегда / слабые условия |

**Типы для «мирного времени» (downtime), когда сюжет стоит на месте:**

- **А. Характерологический** — углубление отношений: ветки открываются по уровню доверия или числу выполненных для NPC побочных квестов (референс: разговоры у костра с Паном между миссиями в Cyberpunk 2077).
- **Б. Экспозиционный** — оживление мира: торговцы, прохожие, напарники обсуждают новости, климат, политику. **Правило: экспозиция вне сюжета необязательна** — заинтересованный игрок сам расспрашивает, остальные пробегают мимо.
- **В. Комедийный и эмоциональный** — сброс напряжения при мрачном основном сюжете: шутки, уют, атмосфера в общении с второстепенными персонажами.

**Реактивность — главный инструмент нарративщика:** диалоги простоя не должны выглядеть мёртвыми — они отвечают на действия игрока через систему флагов. Эталонная матрица второстепенного персонажа (торговец):

- Сюжетный акт не завершён → продаёт и ворчит (характерологический).
- Акт завершён (громкое событие) → «Слыхал, что стряслось? Теперь цены взлетят!» (реактивная экспозиция).
- Игрок помог ему в побочном квесте → личная благодарность + скидка (реактивный эмоциональный).

В демо роль «актов» играют вехи из раздела 3, а роль флагов — таблица триггеров из шага 4 (раздел 4).

### 1.3. Маппинг: типология → модель проекта

| Типология | Носители в демо | Реализация в модели 04 |
|---|---|---|
| Гейт-диалоги | Сюжетные эпизоды именных: Навигатор, Доктор, руководитель | Одноразовые эпизоды с условием на прогресс |
| Реактивные | Барки носителей по вехам матрицы (раздел 3) | Пулы с условиями на флаги мира; таблица триггеров |
| Фоновые | Экспозиционный пласт паспортов фракций; бытовые эпизоды жителей | Повторяемые эпизоды без жёстких условий |
| Характерологический | Личные эпизоды по карме/доверию | Условия на отношения с фракцией и завершённые квесты |
| Экспозиционный | Торговцы: снабженец, ферментатор, мусорщики | Реактивные пулы; всегда опциональны |
| Комедийный/эмоциональный | Тональность внутри правил [[Стиль диалогов]] | Гипербола ~50%, сдвиг тона по карме |

Каждая строка будущих матриц маркируется обоими классификаторами: `гейт/реактивный/фоновый` + `характерологический/экспозиционный/эмоциональный`.

## 3. Сетка вех: глобальная дуга → проекция на фракцию

Вехи берём от глобального статуса демо (дуга из [[01 — Структура прохождения]]) и проецируем на триггер каждой фракции:

| Глобальная веха | Поселения | Культ | Корпорация А | Мусорщики |
|---|---|---|---|---|
| **Завязка** | водный дефицит как фон, быт | обычная торговля, ферментация | изолированный быт бункера, пропаганда | жизнь на окраине станции, сторож как данность |
| **Процесс** | кризис обострён, квесты станции | аммиак/хитин нужны герою, слухи о матрице | подготовка процедуры, кандидат | слухи, торговля с рейдами |
| **Катарсис** | запуск станции (+ нападение как слом) | ритуальный момент цепочки перфузата | исход процедуры | гибель/обход сторожа, третий рейд |
| **Развязка** | окно «типа победы» до нападения | новая реальность после запуска | станция работает — их версия истории | новый статус-кво у станции |

## 4. Шаги работ

1. **Паспорт фракции и речевые профили** — тональность, доминирующие эмоции, темы экспозиционного пласта, маркеры речи/жаргона, запретные темы (по границам знания). По одному паспорту на фракцию. До генерации для каждого именного NPC разработать отдельную карточку по [[Стиль диалогов]]: язык с учётом фракции и положения, приветствия и примеры ответов для трёх отношений по карме.
2. **Матрица реплик** — на каждого носителя: 4 вехи × 3–4 барка; каждая реплика ≤1–2 строки, с пометкой скрытого субтекста курсивом (что она говорит о фракции, а не о сюжете). Каждая строка маркируется по типологии раздела 1.2: `гейт/реактивный/фоновый` + `характерологический/экспозиционный/эмоциональный`.
3. **Карма-слой** — для каждого пула варианты тональности `негатив / норма / позитив` (по [[Стиль диалогов]]): базовый пул — «норма», крайние тона — варианты текста в том же эпизоде, без обязательных отдельных сюжетных веток. Норма: сдержанное приветствие и профессионализм; негатив: недоброжелательное приветствие, сухие односложные ответы; позитив: тёплое приветствие, развёрнутые ответы и шутки. Для каждого именного NPC показать приветствие и ответ во всех трёх отношениях; одной метки тона недостаточно. Короткие барки сохраняют ограничение длины, развёрнутость позитивного ответа проявляется в самом разговоре.
4. **Таблица триггеров** — маппинг `флаг состояния мира → активный пул` (совместимо с моделью [[04 — Модель диалогов и квестов]]: условие на эпизоде).
5. **Валидация** — чек-лист: ёмкость; субтекст; отсутствие утечек за границы знания; гипербола ~50% по [[Стиль диалогов]]; реплика узнаваема без подписи; жаргон только по фракции и положению.
6. **Упаковка в Obsidian** — Markdown с фронтматтером (`type: dialogue-matrix`, `status: draft`, `scope: prologue`, `source` на заметки), викиссылки на канон.
